# 项目实战教训（《World War C》中文全译本）

## 犯过的错误 → 规则

| # | 错误实例 | 根因 | 规则 |
|---|---|---|---|
| 1 | 日期规范化只跑临时文件，主文件漏了 | 脚本未接入主流水线 | 规范化脚本目标=主文件，改后立即验证 |
| 2 | 先改 A4 副本再改主文件 | 主次颠倒 | 内容修改只改主文件，格式版从主文件重新生成 |
| 3 | 删书名作者只删了副本 | 只处理交付面 | 修改永远先主文件再派生物 |
| 4 | 增译"在公寓内"（原文无地点） | 没核对原文就采纳编辑意见 | 编辑意见/AI意见=待核对提议，非事实 |
| 5 | 功能获得→功能增益改正文没改术语表 | 术语表是死文档 | 正文改术语必须同步表 |
| 6 | 用户问"终极版是哪个" | 无版本清单 | 建 VERSION_README（文件=什么+状态） |
| 7 | set_text 整段替换丢 run 格式 | 替换方法不统一 | 逐 run 替换；重建前检查 runs 数 |
| 8 | 页数模拟 typst/weasyprint 三套矛盾结果 | 自嗨式精确 | 不可验证指标不假装精确，先问用户优先级 |
| 9 | edit 误删函数体 | 编辑后不验证 | 编辑文件后立即运行确认 |
| 10 | md 备份不同步 | 修改后不同步派生物 | 主文件改后重新导出 md |
| 11 | 第一轮复盘遗漏深层错误 | 复盘不主动 | 每阶段主动复盘，不等被追问 |

## 判断原则（守住或破防的案例）
- ✅ 守住："COVID这样的病原体"不改——原文就是 a pathogen like COVID
- ✅ 守住："华南海鲜"不改——原文仅 the wet market，未点名
- ❌ 破防：超级星期二句加"在公寓内"——编辑意见未经核对就采纳
- 结论：**改错的代价远大于多花时间核对**

## 成稿标准（七项验收）
准确 / 完整（无漏译、无无依据增译）/ 一致 / 专业 / 自然 / 可追溯 / 合规

## 工具环境备注
- pypdf 读文字层；WeasyPrint 69.0 可做 HTML→PDF 页数估算（非精确）
- 无 LibreOffice、无视觉模型 → OCR 缺口靠文字层+人工
